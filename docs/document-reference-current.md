# Observe finite current document references

Masters can observe an exact published source revision and its exact layout publication for `DEPOSIT_ACCOUNT_ENROLLMENT`. It checks the retained source, ordered legal notices, active catalogs/localizations/locales/types, canonical pins and the currently recognized output profile. This is metadata usability for an exact caller intent; it does not admit a product or verify renderer/font/logo bytes.

`POST /api/v1/document-reference-current-observations` accepts `DocumentReferenceCurrentTarget`. Its `product` binds the actual tenant, product root/product/revision/publication UUIDs and definition digest. `purpose`, `documentType` and `locale` are explicit. The template and layout references use owner `core-common-reference-master-data`, kinds `DOCUMENT_TEMPLATE` and `DOCUMENT_LAYOUT`, `versionFormat: OPAQUE` and the same exact owner `versionText`. Template ID/digest mean immutable source revision ID / `sourceDigest`; layout ID/digest mean immutable layout revision ID / `definitionDigest`. Numeric coercion and locale fallback are refused.

The document type is the actual source template type code, for example `CONTRACT`; the deposit-specific business purpose remains separate. The response echoes the complete target, retained layout definition and native `observedAtEpochMillis` / narrowed `effectiveUntilEpochMillis`. Products must bind that exact echo to their own currently admitted definition and retain their original budget. A response, readback or old receipt cannot create new product authority.

## Explicit activation

The path and its resources are absent by default. Enable `firefly.masters.document-reference.current.enabled` only with strict resource-server issuer/audience/tenant validation, no public permit matchers, a bounded HTTPS issuer set, an actual `DocumentLayoutProfileRegistry` and separate `reader.url`, `reader.username`, `reader.password` settings. The reader username is exactly `masters_document_current_reader`; missing settings cannot fall back to Main's legacy credentials. Secrets belong in deployment secret configuration.

An administrator must provision a separate nonlogin/noninherit/nonowner `masters_document_current_guard` and login/noninherit/nonowner `masters_document_current_reader`, with no role memberships and neither superuser nor bypass/create/replication privileges. Reader database `CREATE`/`TEMP`, base-table access and private-schema usage must be absent. A separately delegated migrator with grant authority and SET membership in the guard applies only `classpath:db/optional/document-reference-current/V38__Document_Reference_Finite_Current.sql` in a dedicated migration history. Ordinary `classpath:db/migration` stays at its existing 36 migrations. Do not baseline, repair or merge this history with the legacy or currency histories.

The optional migration temporarily grants guard CREATE on public only for its own functions/view and revokes it in the same transaction. The guard has SELECT on the seven existing global-master business tables; it cannot modify them. Unlike the currency RLS tables, these legacy template/layout tables are not converted to a new RLS policy. The explicitly guard-owned `security_invoker=false, security_barrier=true` view grants the reader SELECT only on the scoped projection, with no SELECT on underlying tables. Every view read requires the exact private native context for its actual transaction/backend/session and immutable target. Arbitrary SET/GUC values cannot supply this context. Exact role, base/view/function/private ACL, owner and search-path checks precede admission.

The native functions keep `search_path=pg_catalog`. Twelve private SQL aliases delegate the exact existing pure V30 helpers; they set only `pg_catalog,masters_document_current_private`, preventing SQL inlining and resolving the legacy helpers' unqualified sibling calls through the same trusted alias closure. No canonicalization algorithm is copied and V30 is unchanged. Migration and runtime checks pin all helper identities, signatures, return types, languages, volatility, strictness, invoker behavior, source fingerprints, owners, private paths and ACLs. The composite reference helper uses the fully qualified `public.document_template_revision` type. The runtime reader cannot execute or modify the private aliases, acquire private-schema access or replace the guard-owned definitions. A mismatched legacy/helper catalog refuses admission.

## Permission and lifetime

`masters.document-template.current` targets `document-layout-revision:<actual UUID>`. Safe policy context contains the complete product tuple, tenant, purpose, document type and exact source/layout pins. Missing/denied/indeterminate policy or obligations refuse. Main requires the actual verified framework authentication principal; policy is evaluated before native I/O and again after the local transaction with the same principal.

The five-second maximum is intersected with the original paired wall/monotonic budget, principal expiry and native time. Acquisition, policy waits, native work and delivery consume that original budget. The reader uses one owned factory/client/template/manager graph and Spring Data projection. Native technical context writes use a physically writable transaction without allowing business mutations. A known NOT_CURRENT result needs acknowledged rollback and complete cleanup; uncertain commit/cleanup remains unavailable.

Responses use `Cache-Control: no-store`: 400 for malformed targets, 403 for missing current permission, 409 for a safely established native noncurrent result and 503 for unavailable/uncertain observation. The endpoint bypasses transport response reuse; historical layout GET/resolve is not this current observation.

The original OpenAPI producer declares this real controller with an unavailable metadata-only service under `openapi-gen`; it creates no native resource or successful business substitute. New SDK transport must come from that running producer and the original Generator. Source tests do not qualify native schemas, generated SDK operation execution, service-controlled assets, HTML/PDF, signing or legal/financial/product admission.
